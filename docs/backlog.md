## Maps & Places epic (scope + phasing in ADR-0106)

The Map is the last unbuilt core tab. [ADR-0106](decisions/0106-maps-and-places-epic-scope-and-phasing.md) is the frame: one mode-re-emphasized tab, picker-first, list-of-pins before an embedded map, filters that are pure client-side derivation. All three follow-on sessions are done: the **design session** ([ADR-0109](decisions/0109-map-tab-design.md) + `mockups/map-tab-v1.html`: list-first tab, Index-grammar filters, category-coloured pins, geolocation UX, near-me, forms, ADR-0107's zone chip; resolves ADR-0106's open design questions), **BE-arch** ([ADR-0108](decisions/0108-maps-and-places-backend-architecture-key-model-and-cost.md): a two-key split — public browser key for the Maps JS API only; a server key for Places New + Routes behind a thin backend proxy on the existing `places` module — `geo-tz` server-side for `Place.timezone`, the `Place` row as the cache with `@@unique([tripId, googlePlaceId])`), and **FE-arch** ([ADR-0110](decisions/0110-maps-and-places-frontend-architecture.md): one shared search core [`lib/usePlaceSearch.ts` hook + two proxy calls on `lib/api.ts`], the place-usage derivation [`lib/place-usage.ts`, feeding both filter chips and pin colour], per-event zone threading through `lib/places.ts`/`lib/time.ts` [resolving ADR-0107 §7 — `Event.displayTimezone` is a manual override, derived by default], and the context-aware `setActiveDate`). **All six phases have shipped** — Phase 6, the rendered map, in session 133 to [ADR-0121](decisions/0121-embedded-map-phase-6-design.md). What is left of the epic is the **paid-Routes enhancement** sequenced after it (live ETAs; a second cost envelope, a second proxy route, and a 10-waypoint Essentials ceiling — ADR-0121 §1/§14), plus the non-code items on the Phase-6 line below (the human visual pass, the cloud styles, staging vars, and two questions left open by decision). ## Documents: performance & caching (two parallel tasks — see `planning/2026-07-17-session-29-document-caching-and-fast-uploads.md`)

Decomposed to run simultaneously; disjoint file ownership (map in the session-29 note). Both **Proposed**.

- **Document blob read caching (ADR-0055)** — a read-through, ciphertext-only cache: server two-tier (in-memory LRU bounded by bytes + local-FS tier) wired into `storage.ts` `getObject`/`putObject`/`deleteObject`, keyed by the immutable `fileRef`; plus a client Cache-API read cache in `fetchDocumentContent`. Skips the repeat S3 GET + network fetch and closes the offline-document-reads gap (CLAUDE.md rule 5 / ADR-0042). New env: `DOC_CACHE_DIR` / `DOC_CACHE_MAX_BYTES` / `DOC_CACHE_DISABLED`.
- **Faster document uploads (ADR-0056)** — move uploads onto the offline outbox: close the upload sheet instantly, queue a `uploadDocument` op carrying the file `Blob`, flush in the background (offline-capable); make `documents.service.create` idempotent on a duplicate client `id` (no 500, no orphaned second blob on retry).
- **Streaming server ingest** (deferred follow-up) — stream multipart → encrypt → S3 multipart upload, dropping the full in-memory buffer + base64 inflation. Touches `storage.ts`/`putObject`, so sequence it _after_ the read-cache task to avoid a merge fight.
- **Redis for documents** (deferred) — a shared cross-instance read cache and/or upload write-buffer only matter past one backend instance (ADR-0031); Redis stays reserved for its earmarked BullMQ role until then.

- **The filter/search reveal is shared** — **done (2026-07-26, session 129; [ADR-0120](decisions/0120-filter-reveal-is-shared-infrastructure.md)):** ADR-0098 §4's motion pass had two halves and only the collapse was generalized at build time (`ui/primitives/Collapsible`); the **per-row filter reveal** stayed a one-off on the Index bookings screen — a `BookingRow`-typed `visibleRows`, a `.index .idx-row` rule capped at `max-height: 140px`, and the wrapper markup copy-pasted at each of its three lists. So the **Map**, built on the same filter grammar (ADR-0109 §2 — same chips, same `SearchOverlay`, same accent), `.filter()`ed rows out of the array and jumped. Now `lib/filter-reveal.ts` (`revealRows` + `countVisible`/`visibleItems`; the caller keeps the predicate, and `index-bookings.ts`'s `visibleRows` is just the bookings one) + `ui/primitives/RevealList`/`RevealRow` (unscoped `.wp-reveal`, motion-ramp durations, `renderBefore` for group headers outside the collapsing wrapper). Two things the one-off never had: a hidden row is **`inert`** (it stays mounted to animate out, so it was focusable and read aloud), and the collapse is a **`0fr`/`1fr` grid track** instead of a per-surface `max-height` cap — with a layout-neutral clip bleed so a row's shadow/focus ring/next-stop ring isn't sheared (verified in a browser: collapsed rows measure 0px, the amber ring renders whole). The Map's chips, `אולי` toggle, and both search halves inherit it with no new mechanism. **Amended the same day (session 130), on the owner's call — _every_ list change is animated:** `כל הימים` and the day strip's day became predicates over the whole trip's places (rows leave and arrive in place, the row nodes reused rather than the list rebuilt), and a pure **re-order** — `קרוב עכשיו`, and any ordering control after it — slides its rows via FLIP (`lib/useFlipRows.ts`, WAAPI so it never fights the reveal's own transform/`transition-delay`, measured only when the row order/visibility actually changed), wired inside `RevealList` so no call site opts in. Verifying it turned up a real bug in `lib/useGeolocation.ts` (the liveness ref was cleared on unmount and never re-armed, so a remount discarded every fix and `קרוב עכשיו` sat on `מאתר…` in dev) — one line + a regression test. A filtered-out row is now hidden-in-DOM rather than absent — count `countVisible`, not `rows.length`.
- **`SearchOverlay` beyond bookings** (from session 63, ADR-0101) — the full-screen search-mode primitive (`ui/primitives/SearchOverlay.tsx`) is wired up for the Index bookings screen and the Map (ADR-0109/0115). A documents search (or any other "type to filter, on a full screen" need) should adopt it directly rather than growing a second one-off, whenever one is actually needed — and it gets the reveal motion for free by rendering its rows through `RevealList` (ADR-0120).
- **Search bookings by linked place** (from session 64, ADR-0102) — the Index bookings search matches title/confirmation code/category vocabulary via an extensible term array (`lib/index-bookings.ts`'s `searchTerms`); a linked place's name was explicitly named as the next facet to add, once wanted — a one-line push into that array, not a new mechanism.
