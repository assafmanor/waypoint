## Maps & Places epic (scope + phasing in ADR-0106)

The Map is the last unbuilt core tab. [ADR-0106](decisions/0106-maps-and-places-epic-scope-and-phasing.md) is the frame: one mode-re-emphasized tab, picker-first, list-of-pins before an embedded map, filters that are pure client-side derivation. All three follow-on sessions are done: the **design session** ([ADR-0109](decisions/0109-map-tab-design.md) + `mockups/map-tab-v1.html`: list-first tab, Index-grammar filters, category-coloured pins, geolocation UX, near-me, forms, ADR-0107's zone chip; resolves ADR-0106's open design questions), **BE-arch** ([ADR-0108](decisions/0108-maps-and-places-backend-architecture-key-model-and-cost.md): a two-key split — public browser key for the Maps JS API only; a server key for Places New + Routes behind a thin backend proxy on the existing `places` module — `geo-tz` server-side for `Place.timezone`, the `Place` row as the cache with `@@unique([tripId, googlePlaceId])`), and **FE-arch** ([ADR-0110](decisions/0110-maps-and-places-frontend-architecture.md): one shared search core [`lib/usePlaceSearch.ts` hook + two proxy calls on `lib/api.ts`], the place-usage derivation [`lib/place-usage.ts`, feeding both filter chips and pin colour], per-event zone threading through `lib/places.ts`/`lib/time.ts` [resolving ADR-0107 §7 — `Event.displayTimezone` is a manual override, derived by default], and the context-aware `setActiveDate`). **Phases 0–5 have shipped**; the epic's remaining work is **Phase 6** (the embedded map — designed 2026-07-26 in [ADR-0121](decisions/0121-embedded-map-phase-6-design.md), blocked only on the human Google Cloud gate) and the paid-Routes enhancement sequenced after it.
