## Maps & Places epic (scope + phasing in ADR-0106)

The Map is the last unbuilt core tab. [ADR-0106](decisions/0106-maps-and-places-epic-scope-and-phasing.md) is the frame: one mode-re-emphasized tab, picker-first, list-of-pins before an embedded map, filters that are pure client-side derivation. All three follow-on sessions are done: the **design session** ([ADR-0109](decisions/0109-map-tab-design.md) + `mockups/map-tab-v1.html`: list-first tab, Index-grammar filters, category-coloured pins, geolocation UX, near-me, forms, ADR-0107's zone chip; resolves ADR-0106's open design questions), **BE-arch** ([ADR-0108](decisions/0108-maps-and-places-backend-architecture-key-model-and-cost.md): a two-key split — public browser key for the Maps JS API only; a server key for Places New + Routes behind a thin backend proxy on the existing `places` module — `geo-tz` server-side for `Place.timezone`, the `Place` row as the cache with `@@unique([tripId, googlePlaceId])`), and **FE-arch** ([ADR-0110](decisions/0110-maps-and-places-frontend-architecture.md): one shared search core [`lib/usePlaceSearch.ts` hook + two proxy calls on `lib/api.ts`], the place-usage derivation [`lib/place-usage.ts`, feeding both filter chips and pin colour], per-event zone threading through `lib/places.ts`/`lib/time.ts` [resolving ADR-0107 §7 — `Event.displayTimezone` is a manual override, derived by default], and the context-aware `setActiveDate`). **All six phases have shipped** — Phase 6, the rendered map, in session 133 to [ADR-0121](decisions/0121-embedded-map-phase-6-design.md). What is left of the epic is the **paid-Routes enhancement** sequenced after it (live ETAs; a second cost envelope, a second proxy route, and a 10-waypoint Essentials ceiling — ADR-0121 §1/§14), plus the non-code items on the Phase-6 line below (the human visual pass, the cloud styles, staging vars, and two questions left open by decision). - **Faster document uploads (ADR-0056)** — move uploads onto the offline outbox: close the upload sheet instantly, queue a `uploadDocument` op carrying the file `Blob`, flush in the background (offline-capable); make `documents.service.create` idempotent on a duplicate client `id` (no 500, no orphaned second blob on retry).
- **Streaming server ingest** (deferred follow-up) — stream multipart → encrypt → S3 multipart upload, dropping the full in-memory buffer + base64 inflation. Touches `storage.ts`/`putObject`, so sequence it _after_ the read-cache task to avoid a merge fight.
- **Redis for documents** (deferred) — a shared cross-instance read cache and/or upload write-buffer only matter past one backend instance (ADR-0031); Redis stays reserved for its earmarked BullMQ role until then.
