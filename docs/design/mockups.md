# Mockup catalog

**Status:** ACCEPTED (living index — update it in the same change whenever a mockup is added, or a listed one is superseded/ships)

Interactive HTML mockups live in `mockups/` at the repo root. This is the map of what each one is for, what it promotes/supersedes, and its status relative to the shipped app — read the entry for the surface you're touching, not the whole file. Moved out of the root `CLAUDE.md` (ADR-0097) so a task that never touches design/mockups doesn't load this list.

On conflict between an older mockup and `design-language.md` or an accepted ADR, the newer accepted doc wins — each entry below says so where it applies.

## Writing one

**The procedure is a skill: `.claude/skills/design-mockups/`** ([ADR-0175](../decisions/0175-the-mockup-procedure-is-a-skill.md)) — a working template, the traps that only appear once a file is rendered, and a renderer that shoots every theme × width and reads the measurement table back. It carries the _how_; this section and the ADRs it cites stay the home of the _rules_, so a rule changes in one place only.

**A mockup renders in BOTH themes and carries a toggle** (owner, 2026-08-02; [ADR-0158](../decisions/0158-dark-mode-ships-and-the-ink-a-surface-carries-is-a-token.md) §16). Dark mode ships, so a surface drawn only in light is drawn half. The mechanism is three lines, because a mockup that inlines the app's stylesheets already contains the dark remap, inert: two buttons that set `data-theme` on `<html>` — the same attribute `lib/theme.ts` writes. The mockup's own `mk-*` chrome flips with them (its own variables plus a `:root[data-theme='dark']` block after the light one), or a dark frame is judged on a white page the app never has. Binds on **create or revise**; the older files below are dated records and are not retrofitted.

Two conventions the newer files already follow: inline the app's real CSS with `mockups/tools/inline-app-css.mjs` (an `APP-CSS:` manifest plus a generated `<style data-app-css>` block) rather than hand-copying token values, and **read measurements off the live DOM** in the file rather than typing them into the prose.

Chunking costs three things this app has paid to avoid, all named: [ADR-0150](../decisions/0150-a-form-refuses-at-the-field.md)'s "report every problem in one call" (paging manufactures the second save loop it exists to end), [ADR-0136](../decisions/0136-an-event-can-also-be-booked.md)'s "requires nothing" posture, and the ability to review a hard commitment before signing it. Carries a **head-to-head at 390px with the 80vh fold line drawn** (a sheet shows ~675px of itself on an 844px phone; the round-trip form measures 1570px, 2.3 screens, and the entire return leg falls below the fold) and a **scan of all nine form surfaces** with `<Field>`/control counts from source — of which exactly **one** (`BookingSheet`) is long enough to be a candidate, and only after the round-trip proposal lands, so the proposal would create the app's first form that needs paging. `EventForm` already solves the same problem with `Collapsible` (ADR-0098, four call sites); `CreateTrip` is deliberately minimal (ADR-0032); `MapPlaceForm` explicitly must not grow (ADR-0148 spent a session on its room, and a card that clips cannot host more). States the rule that must live **inside** the primitive or it breaks ADR-0150: a step gate reports every problem in the current step, and the save re-validates everything and **navigates to the first step carrying a problem and marks it**. Recommends: extract `ui/primitives/FormSteps` from the two shipped surfaces (standalone justification, deletes a copy, independent of any round-trip decision); do **not** step `BookingSheet` yet; try `Collapsible` there first. _Revised 2026-08-02 against the notes work (ADR-0152/0153), which lands two hard rules on the primitive and stales three scan rows (corrected: `EventForm` 5 fields/18 controls, `DocumentUploadSheet` 4/10, `DocumentManageSheet` gains `HostNotes`, plus a new `MaybeManageSheet`)._ **(1) `FormSteps` must never animate height.** The obvious step transition animates `max-height` so the sheet does not jump — which is exactly the trap ADR-0152 §6's amendment was written for: `.wp-event-actions` animates `max-height: 0 → 220px`, a fixed cap, clipping notes at about three, and raising it changes the motion of every card (ADR-0140). A step panel now contains a **composer that grows without bound** (a committed note collapses to a chip: `base + N×chip`), so the transition is `translateX`+`opacity` only and the sheet is allowed to resize. **(2) `FormSteps` must commit once, on the last step.** `verbs.create`/`schedule`/`book` now resolve to their created host so notes queue _behind_ it — the outbox is FIFO and a note that overtakes its host is refused — so a per-step "save and continue" would queue a note before its host exists, and would fail only offline. Single-commit is also what keeps ADR-0150's re-validate-everything honest. The composer belongs in the **last** step, with the code and the kind, since all three are shared across both legs. The 1570px measurement is now a **floor**, not a height.

The manual-count control (0 · 3 · 8) is the whole argument: at 0 the two orders are identical, so the choice only matters at volume. **§3 what the tap does from the Index** — ADR-0061 §1's CTA-does-the-thing was written about Plan Home, where all five actions close over PlanHome's own state and **three of five are cross-screen**; three readings drawn (navigate away · sheet over the Index · open-in-place with the verb in the foot, which reuses ADR-0189's idiom and is the only one that contradicts "a derived row has nothing to read"). **§4 the completed-collapse would exist twice** (`CollapseToggle` + `.chk-done-sum` vs the `הושלמו` facet chip), which ADR-0188's retirement list never mentions. **§5 `.chk-ppl` retires with nowhere to go** — three readings, measured. **§6 is the owner's, from a real device:** _"the members are prominent in the creation form but you can barely see it in the main tasks view"_. ADR-0188 §3 decided that deliberately ("a name in the meta line, not an avatar") on the ground that an avatar would be **"a second identity system per row"** — **and that ground expired when [ADR-0189](../decisions/0189-the-editor-uses-the-idiom-the-app-already-had-and-a-task-is-read-where-it-sits.md) put `Avatar` in the editor for this same field**; the row would now be reusing the system the feature already established. Four readings, and the title column is where the cost lands: name-only **201px**, mini-avatar+name **201px** (free), avatar in the trailing slot **167px** — which visibly wraps a long title in the frame itself. **Three render findings §6 produced that reading did not:** this file's own first CSS comment claimed a mini avatar costs no height and was **wrong** — an 18px circle in an 11.5px line box took the row 61px → **68.5px**, a tax on every row including ones with no assignee, and two passes of negative block margin landed it at **61.5px against 61px** (half a pixel, written as measured rather than rounded to the claim); the 167px title column's wrap confirms §6ג's number visually; and the mini-avatar reading fixes something that was never reported — today an **unassigned** task's meta says _nothing at all_, indistinguishable from "assigned to someone whose name did not fit", where the editor's own glyph says `לא משויך`. Interactive: theme · width · **how many manual tasks the trip has (0 · 3 · 8)**. **Renders all four theme×width combinations with the webfonts loaded and no console errors.** **ANSWERED and BUILT — [ADR-0190](../decisions/0190-a-readiness-check-is-a-task-row-and-the-checks-sit-inside-the-urgency-ladder.md)** ([build note](../planning/2026-08-16-tasks-phase-2-built.md)). **The file is deliberately NOT retrofitted**, because §2's answer is a **third order it does not draw**: shown automatics-first and pure-urgency, the owner rejected both — _"prioritized or due, overdue tasks should be on top"_, then _"First but also important above them"_ — giving **urgent → checks → the rest**, in ONE list rather than the two cards drawn here. That is the file working as intended rather than failing: it made both candidate orders concrete enough to be turned down, and its 183px burial measurement is what ruled out the settled one. The rest landed as drawn — checks on both surfaces under `הכל` alone, Plan Home keeping its collapse, the passport pips deleted, and §6's mini-avatar reading (free: 201px title column, 61px row).
