§1 · הסימן — שורה שאומרת שיש עליה מסמך

ADR-0152 §6c gave a row a note mark and fought for its 13px on the app's most crowded line. `lib/attachments.ts` already ships `attachmentCountsByHost` / `attachmentCountFor` — written for exactly this and never called by anything, which is report (b) in one line: the count exists, nothing renders it. The only question a drawing can answer is whether the row survives a second glyph, because a booked event's meta line already carries a place name, a confirmation code, a sync badge and the note mark.

These render the app's own rule, not a hopeful version of it. `eventMetaParts` already drops the place name when a row has a code and a mark (`showPlace = placeName && !(code && (hasMark || placeInTitle))`, ADR-0152 §6c) — so A and B below show the place gone, which is what the shipped app draws. The one case the doc mark actually changes is C: a code and a document but no note. Today `hasMark` counts notes only, so the place stays and the line has to hold four things. That is the whole code change — `hasMark` learns to count both — and C is the drawing of why it is needed.

What the pass changed: two things this section did not set out to find. (1) The only day-card case the doc mark alters is code + document, no note — everywhere else §6c's rule has already dropped the place name — so the code change is one predicate learning to count a second thing, not a new rule. §2 · הצ׳יפ נפתח — הדרך פנימה שלא קיימת

This is report (a), and it is smaller than it sounds. `DocumentChip` renders a title span and one button, and that button detaches. There is no tap in the shipped app that opens an attached file — the viewer exists (`MediaViewer`/`DocumentViewer`, the app's one full-screen reader) and nothing on a host reaches it. The fix is the shape `.note-chip` already uses: its text is a `<button>` because a committed note has to be openable before the host is saved, and its ✕ is a sibling because buttons do not nest.

§3 · איפה מסמך נקרא — `HostDocuments`, בן־הזוג של `HostNotes`

`HostNotes` is one connected component with five hosts, and its own file records why: the second and third copies of eight lines are the shape ADR-0094/0096 exist to stop. Documents are at exactly that moment now — the place card, the booking detail and the expanded day card all want the same list. So: one `HostDocuments`, the same `lib/host-context.ts` derivation, rendered wherever `HostNotes` already is and the host can carry an attachment.

§4 · תצוגת אירוע במצב תכנון — שלושה מכלים

Report (c). Today Plan mode's row tap opens `EventForm`. That form does show the notes and the attachments on an edit — so the content is reachable — but you reach it by opening an editor and scrolling past a title field, an icon picker, a category grid, a place picker and a when field. And on a read-only archived trip `.bld-main` is a `<div>`, not a button, so a finished trip's events cannot be opened at all.

The three containers, over the same day. All three assume the tap changes — the row's tap becomes a read, and `עריכה` moves to the read's own control. That costs one tap on edit and nothing is lost: `עריכה` is already the first row of the `⋯` sheet, the time button already owns the most common builder edit (move it), and drag already owns reorder.

Measured: –
On the prominence: the shipped control is `--cta` text on `--card` behind a dashed `--line` border, which is the app's grammar for an absence — the same dashed treatment `.bld-time.empty` uses to mark "this event has no time". That is why it reads as scaffolding rather than as an invitation. The proposal keeps the control and changes three things: a solid border tinted toward `--cta`, a 5% `--cta` wash, and 44px instead of 40px so it stands on the app's touch floor. It stays neutral — no amber, no teal, no violet — because rule 4 has nothing to lend a document either.
On the order: the reorder is free (it moves rows, it adds none), and §3 already argued why it is right on the read surfaces too. One caveat worth recording rather than discovering: on a create, the attach slot now sits above a notes composer whose `＋` is the form's most-used control, so the composer is one row further down the scroll. At 44px that is 44px, on a form ADR-0155 measures at ~1565px.

מה זה לא עושה

Not here, deliberately. (a) Attaching from the document's side — ADR-0173 §9 deferred it and this session does not reopen it; the one entrance stays the host's form. (b) "Where is this document attached?" on the documents screen — the reverse read, also §9, and it is a real gap but it is a third feature and the owner asked for the ui not to grow. (c) Auto-attaching a parsed boarding pass — §9, wrong layer. (d) A Trip-mode change to how the day card opens — it already expands and that expansion already holds the notes; it gains the documents section (§3 D) and nothing else.
