Layout, crop behaviour and density are honest here; whether a real photo is legible at 40px is the one question this mockup cannot answer.

ADR-0158 §15: an inverted surface is where a paper component breaks. A photo carries its own light, so the credit line under it is the thing to check — it sits on the card, not on the image, precisely so it never fights a bright sky.

What this mockup decides

  • The badge is the thumbnail's frame — same 40×40, same r12, same tap target ("the way to the pin"). The category hue moves from fill to a 2px inset ring, so no hue leaves the budget and no slot is added to a 73px row.
  • A picked icon beats a fetched photo. ADR-0147 stores an icon only when a human picked one, and ADR-0166's founding line is that the trip's opinion is never overwritten by the world's facts. Order: picked icon → photo → derived glyph.
  • Enrichment lands in .map-refs on selection, in a fixed order: hero, credit, summary, hours, way-through. An unselected row costs nothing.
  • Attribution renders on the card, under the image — photographer · license, muted, 11px. 27 of 32 files require it, so this is the default line, not an exception. The 40px badge carries none; it leads here.
  • An English summary is marked with באנגלית and nothing else changes — the text itself takes dir="auto", which is what keeps a Latin run from reordering in the RTL flow (ADR-0118).
  • עוד בגוגל is always present and is never ניווט. The collapsed row keeps exactly one Google exit, so ADR-0121 §8 holds where it was aimed; the second is revealed, differently labelled, and answers a different question. When we know nothing, it is the only thing in the block — which is the 0-of-7 case, so it is the state to get right.
  • Hours carry an "as of". They are the one semi-volatile field, and a stale "open until 18:00" read at 17:50 is this feature's worst failure.

What rendering it found (Chromium, 390×844, DPR 2)

  • The hue ring did not survive the photo, as first written. An inset box-shadow paints above the background and below the children, so the image covered it completely and the badge lost its category entirely. It needs an overlay ::after above the image — which also buys a hairline so a dark ring survives a bright sky. Reading the CSS would not have caught this.
  • The credit line orphaned itself to the wrong edge. It is Latin, so dir="auto" made the whole element LTR — correct internal ordering, then aligned left while every other line in the card sits right. The element must stay RTL and isolate the Latin run inside it: the ltrIsolate half of ADR-0118, not the dir half. This is the mirror of the bug that ADR forbids, and it will recur on every enriched Latin string.
  • Measured heights. Collapsed rows stay at 69–71px — the badge-as-frame costs nothing, which was the whole claim. A fully enriched card is 392px, 46% of a 390×844 viewport; the empty one is 134px with a 44px refs block.
  • Shrinking the hero barely helps, so keep it. Sweeping 132 → 96px moves the card only 392 → 356px, because the height is five stacked elements and not the image. Measured, not guessed: the hero is not the lever it looked like.
  • No horizontal overflow at 390px, and the embedded Japanese run inside the Hebrew summary orders correctly under the browser's own bidi algorithm — worth checking because an enriched summary is third-party prose that can carry any script.
