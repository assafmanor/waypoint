§DThe exit is not the entrance reversed — and the reversal never ran anyway

v1 played its entrance keyframes with reverse and argued that as a feature — "so the two cannot drift apart by being written twice". Building v2 found something worse than a taste problem: written that way, the exit does not play at all.

Reusing the entrance's animation-name and changing only the duration, easing and direction does not start a new animation — it retargets the existing one, which keeps its current time. By the time you close an overlay that has been open for a second, its current time is far past the new --t-quick duration, so the animation is already complete and fill: both paints the reversed end state on frame one.

This is shipped, and it is not only v1's. Driven against the app's real modal.css, a sheet open for 200ms or more is at translateY(200px) with the scrim at 0 the instant .is-closing lands. It plays only if you close within ~140ms of opening (at 60ms: y=130, scrim 0.35). Six rules do this — modal-scrim-in, modal-sheet-in, modal-dialog-in, modal-full-in and both panel-open rules in screens.css — which is every overlay in the app plus ADR-0144's anchored panels. So ADR-0140 §G1's own sentence, "no overlay in the app has an exit at all", is still true; the fix has been in production and has never run.

How it got through is legible in ADR-0140's build log: the durations were "verified by sampling computed styles mid-flight in Chromium" — mid-flight is the one window where it does work. And jsdom has no stylesheet, so the unit suite exercises the zero branch and cannot see it. The fix is one word per rule: give the exit its own @keyframes name instead of reversing the entrance's.

With that fixed, the design question v1 got wrong stands on its own: v2's exit inverts the order (chrome first, scrim last, so the card clears against a still-dimmed room) and uses a shallower scale — .96, not a retrace to .88 — with a downward drift. §EThe token that does not do its job

ADR-0140 added --ease-arrive as "the only overshooting easing — an object that must settle", and every entrance in the app now rides that promise. Both phones below are v2; only the curve differs.

cubic-bezier(.22, 1.16, .36, 1) peaks at 1.0075 of progress. On v1's scale range that is 1.0004 — 0.04% over. Even across a 40px translate it overshoots by 0.3px. A settle nobody can perceive is not a settle, and it is part of why every entrance in the app lands flat. A conventional back-ease, cubic-bezier(.34, 1.56, .64, 1), peaks at ~1.09 — about 12×.

This file does not change the token. --ease-arrive is shared vocabulary owned by ADR-0140 and used by every overlay, the shell route transition and the trip-birth sequence — re-pointing it changes all of them, and that is a decision for whoever owns that ADR. The v2 sheet is built to read on the shipped curve either way; this panel is the evidence and the question.

§FHow the document itself arrives — three candidates

The other half of "not varied": in v1 the page appeared with the same plain fade as everything else, on the one element that is the actual subject. Set NETWORK to cold so the beat is separated from the card's arrival, then open all three.

(a) fade — v1's answer, calm and arguably too quiet. (b) wipe — a clip-path reveal, deliberately not a transform, because that channel belongs to ADR-0062's pinch handler; it reads as a document being scanned. Risk: charming once, possibly fussy on the fiftieth open. (c) mount opens — the letterbox goes from the card's fill to --paper as the page lands, so the frame opens around the document. Nothing but opacity touches the image in any of the three.

needs NETWORK = cold to separate from the card

§GReduced motion still resolves

v2 has four animations where v1 had two, so the correctness case is worth re-checking rather than assuming: with REDUCE on, the exit timer must read 0 and unmount synchronously, or the viewer sits there holding focus.

§HThe sheet

Channel Delay Duration Easing What it does, and why it is separate
scrim 0 --t-deliberate --ease-standard Atmosphere, and it leads — v1 had the card at 40% opacity over an 11% scrim, i.e. arriving before the room dimmed
mount · transform --stagger-step --t-deliberate --ease-arrive scale(.88) + the measured origin translate. Double v1's travel, plus real displacement from the tapped row
mount · opacity --stagger-step --t-quick --ease-standard Split off the transform. Solid early, so the remaining 300ms is spent perceiving movement rather than a fade — the direct fix for the "over in the first quarter" fault
chrome 3 × --stagger-step --t-base --ease-standard Furniture on the object, so it arrives after it. This is what makes the card assemble instead of appearing pre-drawn
document on load §F --ease-standard Its own clock entirely — the bytes land 40ms or 1.4s later, so it can never be a member of the arrival sequence
exit · chrome 0 100ms --ease-exit Goes first. The order inverts, which is half of why it is not a rewind
exit · mount 0 --t-base --ease-exit scale(.96) + 10px down. A shallow drop away, not a retrace to .88
exit · scrim --stagger-step --t-base --ease-exit Leaves last, so the card clears against a still-dimmed room

Every value is from the shipped ramp — no new tokens, and no second --t-cinematic moment. --t-deliberate is a new use of an existing token (it currently serves the return-gesture slide and the Trip→Plan stand-down), which is the right rung for a large surface that v1 was trying to fly at sheet speed.
